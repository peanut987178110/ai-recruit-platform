# AI 招聘与人才发展平台

面向招聘 HR、业务面试官与新人员工的 AI 辅助平台。以**岗位能力模型**为统一底座，
在简历筛选、面试提问、培训考核三个环节提供**带证据的判断建议**，人保留最终决策权。

---

## 一、快速启动

### 方式一：解压即用（推荐）

1. 解压到一个**不含中文与空格**的目录（例如 `D:\ai-recruit`）
2. 双击 `install.bat` —— 需要 Python 3.10+；包内已带构建好的前端，**不需要 Node.js**
3. 双击 `scripts\start-all.bat` —— 浏览器会自动打开
4. 用 **admin / 123456** 登录

首次启动会自动建库并写入演示数据，无需任何手工配置。
整个安装约 2–4 分钟（只需装 Python 依赖）。

### 方式二：从源码运行

从 Git 仓库克隆的版本不含构建产物，因此还需要 Node.js 18+：

```powershell
cd <项目根目录>
.venv\Scripts\python.exe -m uvicorn main:app --host 127.0.0.1 --port 8000
```

或直接双击 `install.bat`（它会检测到缺少前端产物，自动用 npm 构建），
再双击 `scripts\start-all.bat`。

前端由后端一并托管，运行时**只需一个进程**，访问 <http://127.0.0.1:8000>。

改前端代码时，另开 `scripts\start-frontend.bat` 走 Vite 热更新（<http://127.0.0.1:5173>）。

`ANTHROPIC_BASE_URL` / `ANTHROPIC_AUTH_TOKEN` 提供。

未配置时平台仍可完整演示，只是 AI 能力走降级路径并在界面明确标注。

### 技术选型

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 模型编排 | LangChain 1.4 + LangGraph 1.2 | 技能作为 Tool，流水线用显式状态图 |
| 后端 | FastAPI + SQLAlchemy 2.0（异步） | 全异步，与模型调用天然契合 |
| 数据库 | SQLite（可换 PostgreSQL） | 改 `DATABASE_URL` 即可 |
| 前端 | Vue 3 + Vite + ECharts | 无 UI 框架依赖，样式走设计令牌 |
| 检索 | 自研 BM25 变体（中文二元组） | 无分词依赖，千级文档量级够用且零外部依赖 |

### 三个值得说明的设计

**1. 模型自动选型，不硬编码模型名**

`app/llm/registry.py` 从网关拉取可用模型列表，按「家族特征 × 档位」打分挑选。
新模型上线时同家族自动继承打分，不需要改代码。分级路由的动机是成本：
解析走小模型、打分走中模型，成本相差约一个数量级。

**2. AI 输出三段结构强校验**

`app/core/schemas.py` 定义 `AIResult[T]` = 结果体 + 证据体 + 元信息。
结果体按 schema 强校验，枚举越界即判失败；打分类能力证据体为空即判失败；
证据无法在原文定位即丢弃。不完整的结果绝不渲染给用户。

**3. 技能双入口**

`app/agents/skills/impl.py` 里每个技能同时是 REST 接口的实现和 Agent 的工具。
两条路径共用同一份 handler，不会出现「对话能做的事按钮做不了」或两套逻辑漂移。

## 四、关键设计决策

### 1. 否决项分正负极性

PRD 3.1.2 只描述了「必须具备」型否决项（未命中即归零）。但真实岗位还需要
「排除条款」型否决项，例如「简历真实性存疑」——**没有造假迹象才是好事**。

若按同一规则处理，简历真实的候选人会因为「没提到造假」被判为 `absent`
而总分归零。这会把绝大多数好候选人系统性打成 0 分。

因此模型上增加了 `veto_polarity` 字段：

- `positive`（必须具备）：`absent` 或 `mismatch` 即归零。例：学历本科及以上。
- `negative`（排除条款）：**只有 `hit` 才归零**，未提及一律 `absent`。例：简历真实性存疑。

负面否决项同时是纯门禁，不参与加权求和 —— 否则「没有造假」会变成一个白送的正向分数。

### 2. 未体现不计入分母

`absent`（简历未提及）固定 0 分且**不计入加权分母**。信息缺失不等于能力不足，
否则简历写得简略的候选人会被系统性低估。这也是 PRD 3.2.3 明确要求的硬性约束。

### 3. 按能力覆盖超时阈值

PRD 4.3 给同步能力定 20 秒超时，是按「短输出」假设写的。实测中要输出大量结构化
内容的调用（出题、打分）会跑到 60 至 120 秒，一刀切会把正常调用误判为超时并触发降级。

因此 `config.py` 里按能力分别设置超时（出题 300 秒、打分 180 秒等），
研发侧可通过配置调整而不改代码。

### 4. 截断识别与修复

模型输出被 `max_tokens` 截断时，报错原本会以「JSON 解析失败」的面目出现，
排查时看不出真正原因。现在：

- 请求侧检查 `stop_reason == "max_tokens"`，直接报「输出被截断」；
- 解析侧 `_repair_truncated()` 会裁到最后一个完整元素并补齐括号，
  能救回的部分就不丢弃。

### 5. 小样本不展示比例

PRD 3.5.2：单指标样本量不足 30 时显示「数据不足」而非展示比例，
防止小样本波动被当作趋势解读。所有比率型指标共用同一条规则（`_rate()`）。

### 6. 禁止静默降级

三级降级（重试 → 换模型 → 转人工）的每一步都写进元信息与决策日志，
并在界面上明示。使用备用模型或模板兜底时，界面必须标注 ——
否则用户会把兜底结果当作正常结论采信。

### 7. 流水线失败必须落到明确状态

后台流水线（解析 → 打分 → 落库）的失败路径有三条保障：

- 写库冲突退避重试 3 次（批量导入 200 份时 SQLite 写锁竞争必然发生）
- 重试仍失败置为「解析异常」并写明原因，**绝不留在「待解析」** ——
  否则用户在界面上看不到任何错误，只会以为系统卡住了
- 调度器每 5 分钟兜底扫描，把卡在中间状态且超过 5 分钟没更新的记录重新入队

没有打分记录的候选人**不允许**执行采纳/否决（状态机前置校验）。
之前缺这道校验，未完成打分的记录能被推进到面试环节。

### 8. 反作弊分层：只有服务端那层是真防线

在线考试的反作弊分三层，**明确区分「无法绕过」与「仅作线索」**：

| 层 | 措施 | 性质 |
| --- | --- | --- |
| 服务端强制 | 答案不下发、试卷冻结、服务端计时、随机组卷、选项乱序、幂等交卷、限次 | **真防线**，无法绕过 |
| 客户端信号 | 切屏、粘贴、复制、右键、开发者工具、多标签页、交卷速度 | 可绕过，**仅作线索** |
| 人工复核 | 带教人看信号明细与作答内容，决定是否作废（作废返还重考机会） | **最终判定** |

关键判断：客户端信号挡不住有心作弊的人（拔网线、第二台设备都能绕），
所以它们只汇总成风险分，**绝不自动判定作弊**。风险等级只影响
「是否进入人工复核队列」，不影响成绩本身。

把第二层当第三层用（自动判作弊）是最常见的错误设计 ——
既拦不住真作弊，又会冤枉被系统弹窗打断的正常人。

判分链路里有一处容易写错的地方：选项乱序后，考生提交的是**乱序后的字母**，
必须先 `unmap_answer` 还原成题库原始顺序再比对，否则会全员判错。
这条映射做了穷举验证（n=2..5 所有排列与答案组合往返一致）。

### 9. 长输出能力的 token 与超时是配套的

模型输出被 `max_tokens` 截断是这套系统里最隐蔽的故障模式：它以
「JSON 解析失败」的面目出现，排查时看不出真正原因。两道防线：

- 请求侧检查 `stop_reason == "max_tokens"`，直接报「输出被截断」
- 解析侧能救回截断内容：断在结构边界、断在字符串中间两种情况都能补齐
  （`_repair_truncated()` / `_cut_to_structured()`），能救的部分不丢弃

按能力的实际输出量分别设置超时与 token 上限，见 `config.py` 的
`llm_timeout_overrides`。

## 五、合规边界

这些边界是需求分析阶段与法务确认的，代码里做了硬约束：

| 边界 | 实现位置 |
| --- | --- |
| 敏感特征不进入打分链路 | 提示词硬约束 + 输出后置校验 + 代码级字段过滤 |
| 不得单独依据自动化决策做不利决定 | 无「已拒绝」状态，低分档进待定池保留 7 天捞回窗口 |
| 系统管理员不可查看简历正文 | `deps.py` 的 `mask_resume_text()`，查询层强制 |
| 面试官仅可见被指派候选人 | 列表查询按 `assignee_id` 过滤，非前端隐藏 |
| 法务审计不含联系方式 | `mask_contact()` |
| 注入三层防护 | 输入层剥离 + 提示层隔离 + 输出层一致性校验 |
| 全链路可追溯 | 决策日志只追加不可编辑，保留不少于 3 年 |
| 录音需候选人明示同意 | 未同意时降级为手动摘要，不阻断流程 |

## 六、测试

```powershell
# 端到端验收（真实模型调用，覆盖 PRD 各模块验收点）
cd backend
.venv\Scripts\python.exe tests\test_e2e.py

# 全流程联调（通过 HTTP 接口走一遍真实业务链路）
.venv\Scripts\python.exe tests\test_integration.py

# 模型网关连通性冒烟
.venv\Scripts\python.exe tests\smoke_llm.py
```

`test_e2e.py` 覆盖的硬约束：

- 简历解析（四类来源、七类异常兜底）
- 四态区分、未体现不计分、命中不低于 7 分
- 否决项正负极性、负面条款不误伤
- 证据定位准确率 ≥90%、证据为原文逐字片段
- 敏感话题拦截零漏出
- 差集出题、时间预算重排 ≤32 分钟
- 培训章节与能力项一一对应

`test_integration.py` 覆盖：导入 → 打分 → 复核 → 面试 → 培训 → 判卷 →
权限隔离 → 配置变更 → 日志审计 → 看板 → 智能体技能。
