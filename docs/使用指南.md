# 使用指南

## 一、启动

### 最快方式

双击解压目录下的 `scripts\start-all.bat` —— 会自动打开浏览器，
访问 <http://127.0.0.1:8000>，用初始超管账号登录。

前端已由后端一并托管，所以**只需要一个进程**，不必单独开 Node 服务。

（开发时想改前端代码，可以另开 `scripts\start-frontend.bat` 走 Vite 热更新，
地址是 <http://127.0.0.1:5173>。）

关闭：在窗口按 `Ctrl+C`，或直接关掉窗口。

### 重新灌演示数据

数据被改乱了想恢复：

```powershell
cd <项目根目录>
.venv\Scripts\python.exe scripts\demo_seed.py
```

会清空旧数据，重新导入 8 份简历并跑完解析打分，约 2 分钟。
脚本会自己用 admin 账号登录，不需要手工配置。

## 二、账号与登录

### 初始账号

平台首次启动会创建 8 个账号，**密码都是 `123456`**：

| 账号 | 角色 | 能做什么 |
| --- | --- | --- |
| **admin** | 超级管理员 | **拥有全部权限**，可访问所有模块、管理所有账号 |
| hr1 | 招聘 HR | 本人负责岗位的候选人，日常复核与安排面试 |
| hr_lead | HR 负责人 | 全部业务线数据、编辑能力模型、创建账号 |
| mgr1 | 用人经理 | 本部门在招岗位候选人 |
| interviewer1 | 业务面试官 | 仅被指派面试的候选人，出题与评分 |
| mentor1 | 带教人 | 培训方案生成、考核终评 |
| legal1 | 法务审计 | 全量只读（不含联系方式）、审计日志 |

登录页左侧有**一键填充**按钮，点一下自动填好账号密码，方便快速切换角色体验。

### 注册新账号

登录页切到「注册」标签，可自助注册。**可选角色限 4 种**：
招聘 HR、业务面试官、用人经理、带教人。

系统管理员等管理类角色**不能自助注册** —— 否则任何人都能给自己开一个
看全量数据的高权限账号，这类账号必须由 admin 在「账号管理」页创建。

### 管理账号

用 admin 登录后，左侧「账号管理」可以：

- 新建账号（可指定任意角色）
- 停用 / 启用账号（停用后立即无法登录）
- 重置他人密码
- 删除账号

有几条保护规则：
- 不能停用或删除自己的账号
- 非超管不能动超管账号
- HR 负责人只能创建非管理类角色

### 修改自己的密码

左下角点自己的名字 → 「修改密码」。改完需要重新登录。

## 三、模型网关配置

这是**换机器部署后唯一需要做的事**。

登录后进「阈值与参数 → 模型网关」：

1. 填入网关地址（Anthropic 协议兼容，不需要带 `/v1`）
2. 填入访问密钥
3. 点「测试连接」验证 —— 会返回网关可用的模型数量
4. 点「保存并生效」

保存后写入 `backend/.env`，**即时生效，不需要重启**。密钥不回显，
之后想改地址留空密钥即可保留原密钥。

也可以用环境变量提供（优先级更高）：

```powershell
$env:ANTHROPIC_BASE_URL = "https://your-gateway.example.com"
$env:ANTHROPIC_AUTH_TOKEN = "your-token"
```

**不配置也能用**：平台其余功能正常，AI 能力走降级路径并在界面上明确标注。

## 四、先看什么

第一次用，建议按这个顺序走一遍，20 分钟能摸清全部能力：

### 第 1 步：看一个完整的候选人（3 分钟）

左侧「**候选人工作台**」→ 随便点一个候选人。

这是产品的核心界面：
- **左边**是简历原文，**右边**是 AI 的打分和逐项判断
- 点右侧任一能力项，左侧会自动滚动到对应位置并高亮证据片段
- 点能力项右下角的「**查看依据**」，右侧抽屉会展开完整证据链 —— 包含引用原文、
  字段来源、以及"为什么判这个状态"
- 底部是操作区：采纳 / 否决 / 标记疑问

试试键盘操作：`A` 采纳，`D` 否决，`J`/`K` 上下切换候选人。这是为连续复核设计的。

### 第 2 步：看 AI 是怎么炼成的（5 分钟）

左侧「**岗位能力模型**」→ 点「后端开发工程师」。

- 每个岗位 6 个能力项，权重合计 100%
- 注意最后一项标着「**排除条款**」—— 这是「简历真实性存疑」，
  它和普通否决项规则相反（详见下面「设计要点」）
- 点进「**能力模型编辑器**」，看右侧的「**试算区**」：
  勾选历史简历 → 点「用当前草稿试算」，
  就能看到改权重后对不同候选人的打分影响，以及**是否与历史人工结论一致**

这是整个产品最有价值的一屏：让 HR 在保存前就知道标准合不合理。

### 第 3 步：看智能体（3 分钟）

左侧「**智能体助手**」，试试这几个问题：

```
现在有多少候选人在待复核？
解释一下张伟的打分依据
我们的订单幂等规范是怎么要求的？
```

它会自己判断该调用哪个技能，你可以在回答上方看到调用轨迹。

### 第 4 步：切换账号体验权限隔离（5 分钟）

退出登录，用不同账号登录，对比数据范围和可执行操作：

| 用这个账号 | 试什么 |
| --- | --- |
| **admin** | 能进所有模块；但打开候选人详情，**简历正文显示"无权查看"** |
| **legal1** | 打开候选人 → 手机和邮箱显示「已隐藏」 |
| **interviewer1** | 工作台只剩被指派给自己的候选人 |
| **mentor1** | 侧边栏只有「培训考核」 |
| **hr1** | 能复核候选人，但进不了「阈值与参数」，也创建不了账号 |

「阈值与参数」页只有 HR 负责人 / 法务审计 / 系统管理员能进。
用无权限账号直接输 URL 访问，会看到一个说明页。

这些限制不是前端藏起来做样子的——**数据可见范围在后端查询层强制过滤**，
直接调接口同样会被拒（返回 403）。完整的角色权限表在
「账号管理 → 角色与数据范围」。

### 第 5 步：看效果看板（2 分钟）

左侧「**效果看板**」。注意几处细节：

- 「数据不足」的指标 —— 样本少于 30 条时故意不显示比例，
  防止小样本波动被当成趋势误读（PRD 3.5.2）
- 每个指标都标了门槛，以及不达标时的处理（延期放量 / 一票否决）
- 底部的「误杀线索」列表 —— 捞回后通过面试的案例会进这里，是发现模型漏判的入口

## 三、走一遍完整业务流程

想体验端到端，按这个顺序操作：

```
1. 候选人工作台 → 右上「导入简历」
   选岗位、上传文件（或用工作台里已有的候选人）

2. 系统自动解析 → 打分 → 分层
   · 高分档 → 直接进「待安排面试」
   · 中间档 → 进「待复核」，强制人工看
   · 低分档 → 进「待定池」，保留 7 天捞回窗口

3. 在候选人详情页点「采纳」
   → 弹窗里安排面试，题目会在几秒内生成

4. 进「面试日程」→ 打开那一场 → 看分层题目
   · 题目优先针对简历里没体现的能力项（差集出题）
   · 每道题都能看到出题依据和高/中/低评分锚点
   · 可以采纳 / 编辑 / 删除，这些操作就是采纳率的来源

5. 面试结束 → 点「评估报告」
   · 勾选「候选人已同意录音」（不勾会降级为手动摘要）
   · 粘贴逐字稿 → 生成报告
   · 注意：**AI 参考区和你的评分区是分开的**，AI 不会预填任何分数
     （预填会产生锚定效应，损害评价独立性）

6. 「培训考核」→ 生成新方案 → 填名称、选岗位、设时间与考试规则
   · 可在弹窗里直接上传公司文件，上传的资料会用于这次出题
   · 大纲章节与能力项一一对应
   · 题库四类题型，每题都能追溯到知识库出处
   · 点「模拟作答」体验判卷：
     客观题规则自动判；主观题只给要点覆盖分析，**终评分数要你填**
```

## 四、设计要点（为什么这样做）

有三处设计看起来反直觉，但都是有原因的：

### 1. 「未体现」和「不符合」是两回事

- **未体现** = 简历里没提到 → 信息缺失，应该留到面试验证
- **不符合** = 简历里写了但明显不达标 → 能力不足

两者混为一谈的话，把简历写得简略的候选人会被系统性低估。所以「未体现」
固定 0 分且**不计入总分分母**。

### 2. 否决项分两个方向

| 方向 | 规则 | 例子 |
| --- | --- | --- |
| 必须具备 | **未命中**即总分归零 | 学历本科及以上 |
| 排除条款 | **命中**才总分归零 | 简历真实性存疑 |

第二类如果按第一类规则处理，简历真实的候选人会因为「没提到造假」
被判为未命中而总分归零 —— 会把绝大多数好候选人打成 0 分。

在能力模型编辑器里，勾选「否决项」后会出现「否决方向」选择。

### 3. 系统没有「已拒绝」状态

低分候选人进待定池保留 7 天，到期归档。**归档不等于拒绝**，
也不触发任何对外通知。是否拒绝、何时告知，由 HR 在 ATS 里另行操作。

这是需求分析阶段与法务确认的边界：平台不承担不利决定的执行。

## 六、出问题时

**界面显示「模型不可用」**
检查环境变量 `ANTHROPIC_BASE_URL` 和 `ANTHROPIC_AUTH_TOKEN`。
未配置时平台仍可用，但所有 AI 能力走降级路径（界面会标注）。

**界面显示「数据不足」**
这是正确行为，不是故障。样本量少于 30 条时故意不显示比例。

**操作返回 403**
权限问题。看看左下角当前是什么角色 —— 不同角色能做的事不同，
这是按 PRD 权限矩阵设计的。

**想看 AI 做了什么决策**
P-12 →「日志与审计」，或在候选人详情页点「决策日志」。
每条都记录了模型版本、提示词版本、置信度、耗时、是否降级。

**想重置演示数据**
P-12 → 底部（需系统管理员身份），或在后端调 `POST /api/system/reset-demo`。
会清空候选人/面试/培训记录，保留配置与知识库。

## 九、打包到别的电脑

### 生成压缩包

```powershell
cd <项目根目录>
.venv\Scripts\python.exe scripts\pack.py
```

产物在 `dist_packi-recruit-platform-<日期>.zip`，约 2 MB。

包里**不含**依赖（`.venv` / `node_modules`），因为虚拟环境里的路径是绝对路径，
拷到别的机器必坏，而 `node_modules` 有几十万文件。取而代之，
包里带了一个 `install.bat`。

### 在目标机器上

1. **解压**到任意目录（路径别有中文和空格，省得踩坑）
2. **双击 `install.bat`** —— 自动检查环境、建虚拟环境、装依赖、构建前端
   - 需要 Python 3.10+ 和 Node.js 18+，脚本会先检查并提示去官网下载
   - 约 3 至 8 分钟
3. **双击 `scripts\start-all.bat`** —— 启动并自动打开浏览器
4. 用 **admin / 123456** 登录
5. 到「阈值与参数 → 模型网关」填入网关地址与密钥

之后每次启动只需第 3 步。

### 打包内容说明

| 包含 | 不包含 |
| --- | --- |
| 全部源码 | `.venv` 虚拟环境 |
| `frontend/dist` 构建产物 | `node_modules` |
| 知识库文档、岗位模型种子数据 | 运行期数据库 `app.db` |
| 演示账号定义 | 上传的简历文件（可能含真实数据） |
| | 令牌密钥 `secret.key` |

新环境首次启动会自动建库、灌种子数据、生成自己的密钥。

### 依赖清单

`backend/requirements.txt` 保持 **纯 ASCII** —— pip 用系统默认编码读它，
中文 Windows 上是 GBK，注释里带中文会直接安装失败。
改这个文件时请留意。

## 十、培训考核与在线考试

带教人上传公司资料 → AI 生成大纲与题库 → 指派给新人 → 新人在线考试 →
带教人复核。开卷前请先了解反作弊的设计边界。

### 完整流程

**1. 上传公司资料（带教人）**

「培训考核 → 培训方案 → 打开方案 → 资料与指派 → 上传资料」

支持 PDF / Word / 纯文本 / Markdown / Excel。**上传后 AI 出题会优先引用这份资料**，
比通用知识库更贴合公司实际做法。建议先传资料再生成方案 —— 否则题目会明显偏通用。

若资料里直接写着「答案：B」这类内容，上传时会提示先清理，那会显著拉低题目质量。

**2. 生成大纲与题库**

「培训考核 → 生成新方案」，在弹出的表单里填：

| 项目 | 说明 |
|---|---|
| 方案名称 | 留空则自动取「岗位名 + 新人培训方案」 |
| 岗位 | 决定大纲对应哪套能力模型，**选错会生成无关的题** |
| 方案说明 | 给新人看的背景交代，会显示在学习页 |
| 培训时间 | 起止日期。**新人只能在这个区间内开考**，区间外会被服务端拒绝 |
| 考试限时 | 10–180 分钟。这是服务端强制的，新人无法自行加时 |
| 及格分 | 0–100。带教人终评时以此为默认判定线 |
| 公司文件 | 可直接在弹窗里上传，上传即入库并绑定到本方案 |

资料一栏若留空不传，系统会自动引用「资料库」里未被其它方案占用的文件，
并在生成后提示引用了哪几份。若想严格控制出题范围，就手动勾选。

生成后需**确认并发布**，未发布的方案不能指派给新人（避免新人拿到没审过的卷子）。

**3. 指派给新人**

同一个「资料与指派」标签页：

- **选择新人** —— 下拉框可输入姓名或账号搜索，支持「全选搜索结果」、
  按标签单独移除、Esc 关闭。已指派的人默认从候选里隐藏，避免重复勾选；
  点「显示全部」可以看全量。
- **截止天数** —— 从今天算起，逾期会标红提醒。
- **考试次数上限** —— 建议 2 至 3 次，留一次失误机会。

指派后下方会列出名单，带上状态、已用次数与截止日期。

只有被指派的新人才能看到并参加这场考核。

**4. 新人学习与考试**

新人登录后侧边栏只有「我的培训」一项 —— 他看不到任何候选人数据。

点「开始考试」后进入独立全屏页面，中途离开会计时不停。

**5. 带教人复核**

「培训考核 → 复核队列」。有风险的记录会排在上面，可给出终评分数，
或判定作弊作废（作废会**返还一次重考机会**）。

### 反作弊怎么做的

这是这个模块最需要说清楚的部分。**分三层，且只有第一层是真正的防线。**

**第一层：服务端强制（无法绕过）**

| 措施 | 说明 |
| --- | --- |
| 答案不下发 | 判分只在服务端做。客户端打开开发者工具也看不到答案 |
| 试卷冻结 | 开考即固定题目与选项顺序，刷新页面拿到的是同一份卷 |
| 服务端计时 | 倒计时以服务器时间为准，改本地时钟无法延长 |
| 随机组卷 | 每人抽到的题目集合与顺序都不同 |
| 选项乱序 | 同一道题在不同人那里选项顺序不同，防止「第三题选 C」 |
| 交卷幂等 | 重复提交不会重复判分 |
| 限次 | 用完次数后无法再考，需带教人加次数 |

**第二层：客户端信号采集（可绕过，仅作线索）**

记录切屏、失焦时长、粘贴、复制、右键、开发者工具、多标签页、交卷速度异常等，
汇总成一个风险分（正常 / 关注 / 可疑）。

这些**挡不住有心作弊的人** —— 拔网线、用第二台设备都能绕过。
所以它们只记录、只汇总，**绝不自动判定作弊**。

**第三层：人工复核（最终判定）**

风险分高的记录连同信号明细一起呈现给带教人，由人决定是否作废。
这符合平台一贯的「AI 给证据、人做决策」，也避免误伤 ——
切屏可能是因为系统弹窗、输入法切换，甚至一条微信通知。

> **把第二层当第三层用（自动判作弊）是最常见的错误设计。**
> 它既拦不住真作弊，又会冤枉正常人。所以风险等级只影响
> 「是否进入人工复核队列」，不影响成绩本身。

### 风险分怎么算

不同信号权重不同（开发者工具 6 分、粘贴 4 分、切屏 1 分），
单类信号累计上限为权重的 3 倍 —— 否则一个人切屏 50 次会直接判可疑，
而实际上可能只是他的输入法一直抢焦点。

- **≥ 5 分** → 关注
- **≥ 15 分** → 可疑

### 两个视角的差异

| 谁能看到什么 | 新人 | 带教人 |
| --- | --- | --- |
| 自己的成绩 | ✓ | ✓ |
| 自己的能力雷达 | ✓ | ✓ |
| 自己的行为信号明细 | ✗ | ✓ |
| 他人的考试记录 | ✗（403） | ✓ |

考生看不到自己被记录了什么 —— 否则记录本身会变成一种压力，
而且没有实际意义。
