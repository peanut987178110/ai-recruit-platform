# 页面与交互规格

> PRD 里写的是**功能规则**；这份写的是**交互细节**：字段、状态、空态、异常、快捷键。
>
> 为什么单独一份：这些内容在 PRD 里会淹没有效信息，但研发和测试每天都要查。
> 它们是「设计稿到代码」之间最容易丢的那一层 —— 丢了的后果是每个页面各写各的。

---

## 1 全局规范

### 1.1 三种状态必须都有

每个列表页、每个异步区域，必须实现三种状态。**只有正常态 = 没做完。**

| 状态 | 要求 | 反例 |
| --- | --- | --- |
| 加载中 | 骨架屏或明确的 loading，不能白屏 | 白屏 3 秒后突然出现内容 |
| 空态 | 说明**为什么空** + 下一步做什么 | 只显示「暂无数据」 |
| 异常 | 说明原因 + 是否可重试 + 已采取的动作 | 只弹「请求失败」 |

**空态文案要写引导，不是写事实。** 对比：

| ❌ 只陈述事实 | ✅ 给出下一步 |
| --- | --- |
| 暂无面试安排 | 还没有面试指派给你。HR 安排面试时选择你作为面试官后，会出现在这里。 |
| 没有题目 | 点击右上角「生成题目」，系统会按能力缺口与时间预算自动出题。 |
| 暂无候选人 | 点击「导入简历」上传文件，或用工作台里已有的样例候选人体验流程。 |

### 1.2 AI 产出区域的三条视觉规则

| 规则 | 原因 |
| --- | --- |
| AI 产出用**独立底色**（本项目为紫色系） | 让用户一眼分清「这是模型给的」和「这是系统事实」 |
| AI 与人工输入**视觉分离**，不混排 | 评估报告里 AI 参考区与面试官评分区必须分开，防锚定 |
| 降级结果**页面内常驻提示**，不是 5 秒 toast | 用户会把兜底结果当正常结论采信，这是最危险的静默失败 |

### 1.3 危险操作的确认规范

| 操作 | 确认方式 | 必须说明什么 |
| --- | --- | --- |
| 删除账号 | 输入或点击确认 | 不可撤销 |
| 删除业务线 | **强制选迁移目标** | 影响多少条数据 |
| 取消面试 | 必填原因 | 候选人链接会失效 |
| 作废考试 | 二次确认 | **返还考试机会** |

**规律**：确认框里要写**后果**，而不是问「确定吗」。用户需要的是判断依据，
不是一次重复点击。

### 1.4 快捷键

| 键 | 作用 | 场景 |
| --- | --- | --- |
| `J` / `K` | 下一条 / 上一条 | 复核列表 |
| `A` | 采纳 | 复核列表 |
| `D` | 否决 | 复核列表 |

**只在高频重复的场景提供快捷键**（HR 一天要处理几十份简历）。
低频页面加快捷键只会制造误触。

## 2 P-01 登录 / 注册

| 项 | 规格 |
| --- | --- |
| 账号 | 仅字母数字下划线短横线，需校验 |
| 密码 | 强度校验（长度 + 字符类型） |
| 业务线 | **字典下拉**，注册前即可读取；空 = 不限 |
| 角色 | 登录页注册仅 4 种：招聘HR / 业务面试官 / 用人经理 / 带教人 |
| 演示账号 | 一键填充按钮组，含全部 10 个账号 |

**异常**：
- 账号重复 → 「账号「xxx」已被使用，请换一个」
- 角色越权 → 「该角色不支持自助注册。可选：…。系统管理员等角色请由 admin 账号创建。」

## 3 P-02 候选人工作台

### 3.1 字段

| 列 | 说明 |
| --- | --- |
| 候选人 | 姓名 + 岗位 |
| 总分 | 0–100 |
| 置信度 | 0–1；**仅内部用于分流，不向业务方解释为百分比** |
| 档位 | 高分档 / 中间档 / 低分档 |
| 状态 | 待解析 / 待打分 / 待复核 / 待安排面试 / 待定池 / 已归档 |

### 3.2 交互要点

| 要素 | 规格 |
| --- | --- |
| 状态筛选 | 顶部标签页，含数量角标 |
| 关键词搜索 | 姓名 / 岗位 / 技能标签 |
| 批量操作 | **中档禁用批量通过**（见 ADR-003） |
| 可见范围 | 由查询层强制过滤，前端不参与决定 |

### 3.3 可见范围提示

页面底部常驻一条说明，写明当前角色的数据范围。
**这一条不是装饰** —— 隔离是静默的，用户需要知道自己看到的是全集还是子集。

## 4 P-03 简历复核详情

### 4.1 布局

```
┌──────────────────────────────┬──────────────────────┐
│ 简历原文（约 60%）            │ 匹配分 82.2 / 100     │
│  · 关键词高亮                 │ 置信度 0.75           │
│  · 点击能力项 → 定位并高亮证据 │ 能力项列表（含依据数） │
│                              │ 采纳 / 否决 / 标记疑问 │
└──────────────────────────────┴──────────────────────┘
```

### 4.2 证据定位（核心交互）

| 项 | 规格 |
| --- | --- |
| 触发 | 点击任一能力项 |
| 行为 | 左侧原文滚动定位并高亮对应片段 |
| 时限 | **300ms 内完成** |
| 依据数 | 能力项旁显示「查看依据 (4)」 |

**为什么证据定位是核心**：它是「信任」的唯一入口。
一个点不开、看不到依据的分数，用户只有全信或全不信两个选择，两者都让产品失效。

### 4.3 四个动作

| 动作 | 结果 | 备注 |
| --- | --- | --- |
| 采纳 | → 待安排面试 | 一键完成，无需理由 |
| 否决 | → 待定池 | **原因必选**，仅用于优化，不用于考核 HR |
| 标记疑问 | 状态不变 | 可指派用人经理 |
| 退回 | → 待复核 | — |

**默认态**：四个动作**全部不选中**。

### 4.4 异常

| 情况 | 表现 |
| --- | --- |
| 证据无法在原文定位 | 判为失败，转人工，不展示该条 |
| 解析字段缺失 | 转人工补录，**仅显示缺失字段**（不让用户重填全部） |
| 置信度低 | 落入中间档，强制人工复核 |

## 5 P-04 待定池

| 要素 | 规格 |
| --- | --- |
| 保留期 | 7 天，到期自动归档 |
| 剩余时间 | 倒计时，≤2 天标黄 |
| 捞回 | 需填捞回原因 |
| 归档 | **不发送任何通知** |

**归档与拒绝的区别必须写在页面上**，否则用户会以为归档等于拒绝。

## 6 P-05 / P-06 岗位能力模型

### 6.1 能力项字段

| 字段 | 取值 |
| --- | --- |
| 权重 | 数值，同一模型内合计约束 |
| 证据类型 | project / tenure / skill / metric / education |
| 极性 | 正向 / 负向 |
| 是否否决项 | 是 / 否，**整个模型 ≤ 3 个** |

### 6.2 AI 权重建议

| 项 | 规格 |
| --- | --- |
| 展示 | 每个能力项旁显示建议值与方向 |
| 依据 | 一致率 + 样本量 + 数据来源说明 |
| 操作 | 接受 / 忽略，**两者都写日志** |
| 约束 | AI 只能建议，**不能自动改权重** |

## 7 P-07 面试日程

### 7.1 字段

| 列 | 规格 |
| --- | --- |
| 候选人 | 姓名 + 岗位 |
| 轮次 | 初面 / 二面 / 三面 / 终面 / HR面 |
| 面试时间 | 含星期与相对时间（「21 小时后」） |
| 面试官 | 姓名 + 账号 |
| 方式 | 视频 / 现场 / 电话 + 会议号或地点 |
| 录音同意 | 未回复 / 同意 / 不同意 |
| 状态 | 待面试 / 已完成 / 已取消 |

### 7.2 按角色差异

| 角色 | 看到什么 | 能做什么 |
| --- | --- | --- |
| 面试官 | 仅被指派给自己的场次 | 进入会议、出题、报告 |
| HR / HR负责人 | 全部 | 全部 + 复制候选人链接 |
| 用人经理 | 本业务线 | 同 HR，但限本业务线 |
| 其他角色 | 无 | 无 |

**邀请令牌只返回给可安排面试的角色** —— 面试官不应能替候选人点「同意录音」。

### 7.3 空态

> 还没有面试指派给你。HR 安排面试时选择你作为面试官后，会出现在这里。

（对 HR 角色则显示：在候选人复核页点击「采纳」后即可安排面试。）

## 8 P-08 面试准备页

| 区块 | 内容 |
| --- | --- |
| 顶部 | 候选人 + 岗位 + 轮次 + 面试方式 + 时间 + 会议号 + **进入会议** |
| 录音提示 | 按三态显示不同提示（见下） |
| 左栏 | 能力项缺口（按权重降序） |
| 右栏 | 分层题目 + 评分锚点 + 采纳/编辑/删除 |

### 8.1 录音提示三态

| 候选人选择 | 页面提示 |
| --- | --- |
| 同意 | 不提示，可开启录制 |
| 不同意 | **不要开启录制**，面试后手动填摘要 |
| 未回复 | **开场先当面询问**，明确同意前不录制 |

「不同意」与「未回复」必须分开 —— 前者直接走手动摘要，后者还要当面再问一次。
只用一个布尔值记录，两种情况会被混成「没同意」，面试官无法区分该怎么做。

### 8.2 选题与编辑

| 操作 | 说明 |
| --- | --- |
| 采纳 | 计入采纳率统计 |
| 编辑 | 保存后计入采纳率（编辑视为采纳的变体） |
| 删除 | 不计入统计 |
| 展开锚点 | 显示高/中/低三档评分锚点与出题依据 |

## 9 P-09 面试评估报告

### 9.1 布局：AI 区与人工区分离

```
┌────────────────────────┬────────────────────────┐
│ AI 参考区               │ 面试官评分区            │
│  · 逐字稿按能力项归类    │  · 空白的评分输入       │
│  · 锚点对照结果          │  · 结论输入框          │
│  · 建议追问              │  · 提交评分按钮        │
└────────────────────────┴────────────────────────┘
```

**AI 区不得预填任何分数。** 预填会产生锚定效应，使面试官倾向于微调而非独立判断。
这一条是验收标准 A3-5。

### 9.2 录音同意

| 候选人表态 | 页面表现 |
| --- | --- |
| 同意 | 绿底提示，可基于逐字稿生成 |
| 不同意 | 黄底提示，**禁止勾选覆盖**，只能手动摘要 |
| 未回复 | 可勾选「已当面取得同意」，写入日志 |

### 9.3 降级

无法生成时**明确说明原因**并降级为手动摘要，不阻断流程。

## 10 P-10 至 P-14 培训与考核

### 10.1 方案生成（P-11）

| 字段 | 规格 |
| --- | --- |
| 目标岗位 | 从岗位列表选 |
| 培训窗口 | 天数 |
| 参考资料 | 多选，可上传 |
| 考试规则 | 题量、限时、限次、及格线 |

**资料引用要说明**：未勾选时自动引用未被占用的文件，**并明确提示引用了哪几份**。

### 10.2 在线考试（P-13）

| 要素 | 规格 |
| --- | --- |
| 全屏 | 路由 `meta.fullscreen`，隐藏导航 |
| 计时 | **服务端计时**，客户端传值被忽略 |
| 断线恢复 | 刷新/换设备恢复同一份试卷，**不重新计时、不换题** |
| 题目出处 | 每题可追溯知识库引用 |

### 10.3 考核复核（P-14）

| 要素 | 规格 |
| --- | --- |
| 排序 | 按风险分降序 |
| 风险分阈值 | ≥15 可疑，≥5 关注，<5 正常 |
| 信号明细 | 逐项列出次数与封顶说明 |
| 终评 | **主观题分数必须人工填** |
| 作废 | 返还考试机会 |

## 11 P-15 效果看板

| 指标 | 目标 | 不达标时的动作 |
| --- | --- | --- |
| 一致率 | ≥ 0.75 | 校准锚点 |
| 误杀率 | ≤ 5% | 调整阈值 |
| 题目采纳率 | ≥ 60% | 改出题策略 |
| 处理耗时 P95 | ≤ 30s | 检查模型路由 |
| 降级率 | ≤ 3% | 检查网关稳定性 |

**看板的设计原则：每个指标都要能对应一个动作。** 不能对应动作的指标不放上去 ——
它会变成装饰。

## 12 P-16 账号管理

### 12.1 账号表

| 列 | 规格 |
| --- | --- |
| 账号 / 姓名 / 角色 / 业务线 / 部门 / 状态 / 最后登录 | — |
| 操作 | 编辑 / 重置密码 / 停用 / 删除 |

**保护规则**：不能停用或删除自己；非超管不能动超管账号。

### 12.2 业务线字典

| 操作 | 规格 |
| --- | --- |
| 新增 | 名称唯一，32 字以内 |
| 编辑 | 改名**级联**到账号/岗位/知识库，需提示影响范围 |
| 停用 | 不能被新选择，已有数据不受影响 |
| 删除 | 未使用时直接删；**仍被使用时必须选迁移目标** |

管理视图必须显示每条业务线的**引用数量**（账号 / 岗位 / 知识库），
让删除前就能看到影响范围。

## 13 P-17 阈值与参数

| 分组 | 关键项 |
| --- | --- |
| 模型网关 | 地址、Key、可用模型列表 |
| 能力分层选型 | 解析 / 出题 / 判卷 / 嵌入 / 视觉 / 备用 |
| 分层阈值 | 高分档（总分 + 置信度双条件）、中间档 |
| 权限矩阵 | 角色 × 模块 × 动作 |

**网关不可用时必须明确提示「模型未配置，已转人工」**，不能返回看起来正常的默认结果。

## 14 P-18 智能体助手

| 项 | 规格 |
| --- | --- |
| 能力 | 11 项技能 |
| 权限 | **与当前登录角色一致** |
| 写操作 | 只生成「待确认动作」，**由人点确认后执行** |
| 依据 | 回答附原文依据入口 |

**自然语言入口不改变权限边界** —— 助手能做的事必须和当前角色能做的一致。

## 15 P-19 候选人面试邀请（免登录）

| 区块 | 内容 |
| --- | --- |
| 面试信息 | 姓名 / 岗位 / 轮次 / 时间（含星期）/ 时长 / 方式 / 会议号或地点 |
| 入口 | 「进入视频会议」按钮 + 设备检查提示 |
| 录音同意 | 说明用途 + 「不同意不影响结果」+ 同意/不同意按钮 |
| 提示 | 链接仅限本人，时间不便请联系 HR |

### 15.1 移动优先

候选人多在手机上打开。规格：单列、卡片宽度自适应、按钮高度 ≥ 44px、无横向滚动。

### 15.2 三态与错误

| 情况 | 表现 |
| --- | --- |
| 未表态 | 显示两个按钮 |
| 已表态 | 显示「您已选择：X 录音」，开始前可修改 |
| 面试已开始 | 锁定，提示「如需变更请直接告诉面试官」 |
| 链接无效/过期/取消 | 统一提示「邀请链接无效或已过期」 |

| 类型 | 采纳 / 否决 / 面试安排 / 录音合规 / 账号管理 / 降级 / 配置 |
