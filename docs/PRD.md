## 1 产品概述

### 1.1 一句话定义

面向招聘 HR 与业务面试官的 AI 辅助平台。以**岗位能力模型**为统一底座，在
简历筛选、面试提问、培训考核三个环节提供**带证据的判断建议**，人保留最终决策权。

### 1.2 本期交付边界

本期交付 R-01 至 R-27 共 27 个需求，其中 Must 级 20 项、Should 级 5 项、Could 级 2 项（未实现）。
放弃自动拒信、终面决策、情绪推断三类场景的论证见需求分析文档 4.2 节。

### 1.3 模块结构

五个模块，**能力模型为底座**，三个业务模块并列在上，数据回流横向贯穿。

```
        ┌─────────────┐  ┌─────────────┐  ┌─────────────┐
        │ M2 简历筛选 │  │ M3 面试助手 │  │ M4 培训考核 │
        └──────┬──────┘  └──────┬──────┘  └──────┬──────┘
               └────────────────┼────────────────┘
                    ┌───────────▼───────────┐
                    │  M1 岗位能力模型      │  ← 三个模块共用同一份数据
                    └───────────────────────┘
                    ┌───────────────────────┐
                    │ M5 数据回流与效果看板 │  ← 横向贯穿，校准 M1 权重
                    └───────────────────────┘
   平台层：权限与数据隔离 / 决策日志 / 模型路由 / 提示词版本管理
```

| 模块 | 内容 |
| --- | --- |
| M1 岗位能力模型 | 能力项 / 权重 / 证据类型 / 岗位模板 |
| M2 简历筛选 | 解析 / 打分 / 溯源；分层 / 复核 / 待定池 |
| M3 面试助手 | 分层出题 / 评分锚点；报告结构化 / 评估报告 |
| M4 培训考核 | 大纲 / 题库 / 判卷；能力雷达图 / **反作弊（R-24）** |
| M5 数据回流与效果看板 | 否决记录 / 采纳率 / 试用期表现回写 / 权重复盘 |
| 平台层 | 权限与数据隔离 / 决策日志 / 模型路由 / 提示词版本管理 / 智能体助手 |

### 1.4 角色与权限

平台共 **8 个角色**。权限在**查询层**强制，不依赖前端隐藏。

| 角色 | M1 能力模型 | M2 筛选 | M3 面试 | M4 培训 | M5 看板 | 数据可见范围 |
| --- | --- | --- | --- | --- | --- | --- |
| 招聘 HR | 查看 | 全部操作 | 查看、**安排** | 查看 | 本人数据 | 本人负责岗位的全部候选人 |
| HR 负责人 | 编辑 | 全部操作 | 查看、**安排** | 查看 | 全部 | 全部业务线 |
| 用人经理 | 提名调整 | 查看复核结果 | 全部操作（含安排本业务线） | 查看 | 本业务线 | 本业务线在招岗位候选人 |
| 业务面试官 | 无 | 仅看指派候选人 | 出题、评分（**不能安排**） | 无 | 无 | 仅被指派面试的候选人 |
| 带教人 | 查看 | 无 | 无 | 全部操作 | 本人带教 | 本人带教的新人 |
| 新人 | 无 | 无 | 无 | 查看／学习／考试 | 无 | 仅本人被指派的培训与考核 |
| 法务审计 | 查看 | 只读日志 | 只读日志 | 无 | 全部 | 全量只读，**不含联系方式** |
| 系统管理员 | 配置 | 阈值配置 | 配置 | 配置 | 全部 | **不可查看简历正文** |

超级管理员（`admin`）拥有全部权限，用于初始建号与运维。
即便如此，**「不可查看简历正文」这条限制对它同样生效** —— 这是合规要求，不可由权限提升绕过。

#### 权限设计的两条约束

一是**面试官只能看到被指派的候选人**，避免简历在组织内无边界流动；
二是**系统管理员可配置阈值但不可查看简历正文**，防止运维角色成为数据合规的缺口。

这两条由数据合规评估意见明确要求。实现方式为：

| 约束 | 实现位置 | 方式 |
| --- | --- | --- |
| 面试官仅见被指派候选人 | 候选人列表与详情接口 | 查询条件强制加 `assignee_id == 当前用户`，越权访问返回 403 |
| 管理员不可见简历正文 | 文本输出前统一过 `mask_resume_text()` | 返回占位文本而非正文 |
| 法务审计不含联系方式 | 输出前统一过 `mask_contact()` | 手机与邮箱替换为「已隐藏」 |
| 业务线隔离 | 列表与知识库检索 | 按 `business_line` 过滤，含知识库检索路径；取值来自受控字典 |

#### 自助注册的角色限制

开放自助注册，但**只允许 4 种非管理类角色**：招聘 HR、业务面试官、用人经理、带教人。
系统管理员、HR 负责人、法务审计、新人必须由管理员创建。

原因：自助注册若开放高权限角色，任何人都能给自己开一个看全量数据的账号，权限矩阵形同虚设。

#### 业务线字典（R-26）

业务线是**数据隔离的边界**：用人经理按业务线看候选人，知识库按业务线检索。
所以它不能是自由文本 —— 账号填「电商业务线」、岗位填「电商线」，字符串对不上，
这位经理就一个候选人都看不到，而且系统不会给出任何提示。

业务线在 P-16 账号管理页维护，账号、岗位、知识库的业务线**只能从字典中选择**，后端同样校验。

| 操作 | 谁可以 | 规则 |
| --- | --- | --- |
| 查看列表 | 所有人（含未登录的注册页） | 只返回启用项的名称与说明 |
| 新增 | HR 负责人、超管 | 名称 32 字以内，不可重名 |
| 改名 | 同上 | **在同一事务里级联**到所有引用它的账号、岗位、知识库，隔离不断 |
| 停用 | 同上 | 不能再被新选择，已有数据不受影响；编辑账号时原值显示为「（已停用）」 |
| 删除 | 同上 | 未被引用可直接删；**仍被引用时必须指定迁移目标**，否则拒绝 |

管理视图显示每条业务线被多少账号、岗位、知识库文档引用，删除前就能看到影响范围。

**为什么删除要强制迁移**：直接删掉一条在用的业务线，那些账号和岗位会属于一个不存在的业务线，
用人经理从此看不到本该看到的候选人。强制迁移或改用停用，是让这种失效不可能静默发生。

**附带修正的隔离缺陷**：候选人列表对用人经理的隔离，判断条件曾写成「是否填了部门」，
过滤却按业务线 —— 没填部门但填了业务线的经理会看到全部候选人。已改为按业务线判断。

#### 编辑账号

账号创建后可修改姓名、角色、业务线与部门。选错业务线或人员调岗，
都应当改账号而不是删号重建 —— 删号会丢掉这个人名下的面试记录与带教关系。
授予系统管理员与 HR 负责人角色仍只能由超管操作，每次修改写入决策日志。

### 2.2 核心流程

简历主链路的状态流转如下。**状态机是开发与测试对齐的关键，每个状态的进入条件与可执行动作必须唯一。**

| 状态 | 进入条件 | 可执行动作 | 流向 |
| --- | --- | --- | --- |
| 待解析 | ATS 推送或手工导入 | 无，系统自动处理 | 解析成功转待打分，失败转解析异常 |
| 解析异常 | 字段抽取失败或文件损坏 | 人工补录、重新上传 | 补录完成转待打分 |
| 待打分 | 解析完成且岗位已绑定能力模型 | 无，系统自动处理 | 打分完成按分层流转 |
| 待安排面试 | 匹配分进入高分档 | 安排面试、退回复核 | 进入面试流程 |
| 待复核 | 匹配分进入中间档 | 采纳、否决、标记疑问 | 采纳转待安排面试，否决转待定池 |
| 待定池 | 匹配分进入低分档或被否决 | 捞回、到期归档 | 捞回转待复核，到期转已归档 |
| 已归档 | 待定池停留满 7 天 | 仅查看 | 终态 |

#### 为什么没有「已拒绝」状态

**系统不提供拒绝动作。** 低分候选人进入待定池并在 7 天后归档，归档不等于拒绝，也不触发任何对外通知。
是否拒绝、何时告知由 HR 在 ATS 中另行操作。

这是需求分析阶段与法务确认的边界：**平台不承担不利决定的执行。**

#### 分层阈值默认值

| 档位 | 默认阈值 | 预期占比 | 流转与约束 |
| --- | --- | --- | --- |
| 高分档 | 置信度 0.85 以上**且**总分 75 以上 | 约 9% | 直接转待安排面试，HR 可退回复核 |
| 中间档 | 不满足高分档且总分 45 以上 | 约 34% | 强制人工复核，**不允许批量一键通过** |
| 低分档 | 总分 45 以下或触发否决项 | 约 57% | 转待定池，保留 7 天，到期归档 |

阈值在 P-12 后台配置，**调整即时生效不需发版**；每次调整记录操作人、调整前后值、生效时间，
并在效果看板标注变更点便于归因。

中间档禁用批量通过是**有意增加操作成本**，因为这部分恰是模型最没把握的样本。

### 2.3 通用交互规范

| 规范 | 规则 | 原因 |
| --- | --- | --- |
| AI 内容标识 | AI 生成内容统一加浅蓝底标识，与人工录入内容视觉区分 | 避免用户误以为是既有数据 |
| 查看依据 | 所有 AI 结论旁提供「查看依据」，右侧抽屉展开，不跳转页面 | 保证复核动作不被打断 |
| 按钮默认态 | 采纳与否决按钮**不设默认选中**，不做倒计时自动通过 | 防止用户无意识批量放行 |
| 加载反馈 | 超过 3 秒显示骨架屏与预计剩余时间，超过 30 秒转后台任务并站内提醒 | 长耗时操作不阻塞 |
| 筛选保持 | 列表页支持按岗位、时间、来源渠道筛选，条件在会话内保持 | 刷新不丢上下文 |
| 二次确认 | 关键操作（否决、捞回、批量导入、作废考核）确认文案必须包含影响数量 | 例如「将否决 12 名候选人」 |
| 降级标识 | 任何降级（重试成功、切换备用模型、模板兜底）**必须界面明示** | 禁止静默降级，否则用户会把兜底结果当正常结论采信 |

## 3 功能需求

### M1 岗位能力模型（R-01）

#### 3.1.1 功能说明

能力模型是平台底座，定义某岗位的录用标准。**三个业务模块共用同一份数据**：
筛选用它打分，面试用它出题，培训用它设考核项。模型支持从模板派生，新岗位只需调整差异项。

#### 3.1.2 字段定义（P-06 能力模型编辑器）

| 字段 | 类型 | 必填 | 默认值 | 规则与约束 |
| --- | --- | --- | --- | --- |
| 岗位名称 | 文本 | 是 | 空 | 50 字以内，同一业务线下不可重名 |
| 岗位序列 | 单选 | 是 | 空 | 技术／产品／运营／职能，决定可选模板范围 |
| 职级区间 | 范围选择 | 是 | 空 | 起止职级，用于区分同岗不同级的标准差异 |
| 能力项名称 | 文本 | 是 | 空 | 30 字以内，**须可被证据验证**，不可写抽象词如「有潜力」 |
| 能力项权重 | 数值 | 是 | 均分 | 1 至 10 整数，系统实时换算为百分比并校验总和 |
| 证据类型 | 多选 | 是 | 项目经历 | 项目经历／任职履历／技能标签／量化成果／教育背景 |
| 判定说明 | 长文本 | 是 | 空 | 200 字以内，描述什么样的表述算命中，作为模型判断依据 |
| 是否否决项 | 开关 | 否 | 关 | 开启后该项未命中则总分置为 0 并标记原因 |
| 否决项极性 | 单选 | 否 | 必须具备 | **必须具备**（无则否决）／**必须没有**（有则否决），用于排除条款 |
| 模型版本号 | 自动生成 | 是 | v1 | 每次保存自动递增，历史版本可查看与回滚 |
| 启用状态 | 开关 | 是 | 停用 | 停用状态不参与打分，新建默认停用需显式启用 |

#### 3.1.3 交互规则

- **权重总和不等于 100% 时，保存按钮置灰并提示当前差额，不做自动归一化** ——
  避免用户以为已生效实则被系统改过。
- 编辑器提供**试算区**：选择历史简历实时查看打分结果与证据，用户可在保存前判断标准是否合理。
- 修改已启用模型时，弹窗提示影响范围（在招岗位数、在库候选人数），确认后生成新版本，**不影响已完成打分的历史记录**。
- **否决项数量上限为 3 个**，超出时禁止添加并提示。否决项过多会使打分退化为硬性筛选，失去模型意义。

#### 3.1.4 验收标准

| 编号 | 验收点 |
| --- | --- |
| A1-1 | 新建岗位可从同序列模板派生，派生后能力项与权重完整继承，**修改不回写原模板** |
| A1-2 | 权重总和校验生效，不足或超出均无法保存且提示差额 |
| A1-3 | 试算区返回结果包含每个能力项的得分与对应证据位置 |
| A1-4 | 修改已启用模型后生成新版本号，历史打分记录仍显示当时使用的版本 |
| A1-5 | 否决项未命中时总分为 0，界面明确显示触发了哪一条否决项 |

支持 PDF、Word、图片（JPG/PNG）、邮件正文四类来源。解析产出结构化字段，作为后续打分输入。

| 抽取字段 | 必须 | 规则与异常处理 |

| 工作经历 | 是 | 按公司、职位、起止时间、职责描述分条存储，时间缺失标记待确认 |

#### 3.2.2 解析异常兜底矩阵

| 异常类型 | 系统行为 | 用户可见提示 | 后续动作 |
| --- | --- | --- | --- |
| 文件损坏或加密 | 转解析异常 | 文件无法打开，请重新上传 | 支持重新上传，原记录保留 |
| 扫描件清晰度不足 | 尽力抽取并标记 | 部分字段识别置信度低，请核对 | 低置信字段黄底高亮，需人工确认后才可打分 |
| 非简历文件 | 拒绝入库 | 该文件不是简历，已跳过 | 批量导入时列入失败清单可下载 |
| 关键字段缺失 | 转人工补录 | 缺少姓名，请补充后继续 | 补录界面仅显示缺失字段，不要求重填全部 |
| 单文件多人简历 | 拆分并提示 | 检测到 3 份简历，已拆分 | 拆分结果需人工确认后入库 |
| 超大文件 | 拒绝并提示 | 文件超过限制，请压缩后上传 | 不进入异步队列 |

**核心原则：任何异常都不得静默丢弃。** 每条失败都必须有可见提示与下一步动作。

#### 3.2.3 匹配打分与证据溯源（R-03、R-04）

| 输出项 | 取值 | 规则 |
| --- | --- | --- |
| 总分 | 0 至 100 | 各能力项得分按权重加权求和，触发否决项时直接为 0 |
| 能力项状态 | **四态** | 命中／部分命中／未体现／不符合，**未体现与不符合必须区分** |
| 能力项得分 | 0 至 10 | 仅命中与部分命中给分，未体现固定为 0 且不计入分母 |
| 证据引用 | 结构化 | 含简历片段原文、字段来源、字符起止位置，供前端高亮定位 |
| 置信度 | 0 至 1 | 决定分层归属，**不在 HR 界面直接展示数值**，仅用于分流 |
| 风险提示 | 标签 | 履历断档超 6 个月、平均在职不足 1 年、职级跨越异常等**客观事实**提示 |

**未体现与不符合必须区分**：简历里没提到某项能力是信息缺失，应当在面试中验证；
简历里写了但明显不符合才是能力不足。两者混为一谈会把表述简略的候选人误判为能力差。

**无证据不给分**：模型找不到支撑片段时该项必须输出「未体现」，不允许凭岗位常识推测给分。
此为硬性约束 —— 实现上，打分类能力若返回空证据体，**整个调用判为失败并走降级**，
而不是渲染一个没有依据的分数给用户。

**风险提示只陈述客观事实，不做主观归因**：系统输出「近三年任职 4 家公司」，不输出「稳定性差」。

### M3 面试助手（R-09、R-10、R-14、R-25、R-27）

#### 3.3.1 出题逻辑

**出题输入为简历结构化数据与岗位能力模型的差集**，即优先针对简历中未体现或部分命中的能力项生成问题。
已充分证明的能力项**最多生成 1 道确认题**，避免面试时间浪费在已知信息上。

| 层级 | 题量 | 考察目的 | 生成规则 |
| --- | --- | --- | --- |
| 基础考察 | 2 至 3 道 | 确认简历基本事实 | 针对职责描述，问具体做了什么、团队规模、个人负责部分 |
| 项目深挖 | 3 至 5 道 | 验证深度与真实参与度 | 针对量化成果追问实现路径与数据来源，追问决策取舍 |
| 压力追问 | 2 道 | 判断边界与应变 | 针对方案的薄弱处提问，或假设条件变化后如何调整 |
| 真实性验证 | 2 道 | 交叉核验 | 同一事实从不同侧面提问，检查表述是否自洽 |

**差集出题是本产品的核心设计，且模型会违反它** —— 实测中它会给两个已证明的能力项各出三道题，
把题目全堆在已经验证过的信息上。因此出题后有一道**强制约束**：

| 类型 | 处理 |
| --- | --- |
| 排除条款（否决项中的「必须没有」） | **最多 1 道，且只做真实性交叉核验**。这类条款是给 HR 判断合规风险的，不是让候选人当面回答「你有没有造假」，模型会把它当普通缺口项猛出题 |
| 普通缺口项 | 优先保留，这是面试要验证的重点 |
| 已证明项 | 每项最多 1 道确认题 |

#### 3.3.2 题目输出字段

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 题目正文 | 是 | 150 字以内，**单一问题不得多问并列**，禁止出现敏感信息相关提问 |
| 考察能力项 | 是 | 关联至 M1 中的具体能力项 ID，一题对应一项 |
| 出题依据 | 是 | 说明为何问这道题，引用简历原文片段或标注该能力项未体现 |
| 评分锚点 | 是 | 高中低三档答案特征描述，每档 60 字以内，供面试官现场对照 |
| 预计时长 | 是 | 分钟数，用于面试官按时间预算取舍题目 |
| 追问建议 | 否 | 候选人回答含糊时的一句追问方向 |

**禁止生成涉及婚育、年龄、生育计划、宗教、户籍、政治面貌的题目。**
此为提示词硬约束加**输出后置校验**双重拦截，命中则整条丢弃并记录日志。

面试官可对每道题做**采纳、删除、编辑**三种操作，操作行为即为采纳率的统计来源，不需要额外打分。

生成结果可按时间预算重排：选择 30 分钟或 60 分钟，系统按预计时长与能力项权重自动取舍题目。

#### 3.3.3 面试评估报告（R-14）

面试结束后生成报告，目标是让面试官**零额外操作**即产出结构化评价。

| 报告区块 | 内容定义 |
| --- | --- |
| 基本信息 | 候选人、岗位、面试官、时长、面试轮次 |
| 按能力项归类 | 将问答对匹配到对应能力项，每项给出候选人回答摘要与锚点对照结果 |
| 未覆盖能力项 | 本轮未涉及的能力项清单，**供下一轮面试官接续，避免重复或遗漏** |
| 原始逐字稿 | 完整逐字稿，折叠展示，支持按发言人分段与关键词检索 |
| 评分录入 | 面试官逐项打分（1 至 5 分）并给整体结论，**AI 不预填分数** |
| AI 建议参考 | 基于回答给出的观察点，明确标注为参考，与面试官评分区域**视觉分离** |

**AI 不预填面试官评分。** 预填会产生锚定效应，使面试官倾向于微调而非独立判断，直接损害评价独立性。

> **实现边界**：逐字稿以粘贴或上传文本方式进入系统，音频转写为外部依赖，见需求分析文档 2.3 节。
> 转写之后的全部处理链路（归类、摘要、锚点对照、报告生成）已完整实现。

#### 3.3.4 面试安排与指派（R-25）

**面试官必须显式选择。** 此前未指定面试官时会静默挂到「第一个业务面试官」名下，
结果所有面试都堆给了同一个人，其他面试官的日程是空的。现在不选面试官无法提交。

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 面试轮次 | 是 | 初面／二面／三面／终面／HR面；同一候选人同一轮次只能有一场待进行 |
| 面试时间 | 是 | 不早于昨天、不晚于 180 天后；默认明天上午 10 点 |
| 时长 | 是 | 30／45／60／90 分钟，决定出题的时间预算 |
| 面试官 | 是 | 业务面试官或用人经理，须为启用账号 |
| 面试方式 | 是 | 视频／现场／电话，见 3.3.5 |
| 备注 | 否 | 200 字以内 |

**面试官推荐排序**：下拉框按「同业务线 → 不限业务线 → 其它业务线」分组，
组内业务面试官在前、待面试场次少的在前，每项显示姓名、账号、部门与当前待面试场数 ——
安排人要看出谁更合适、谁更空，而不是在平铺名单里凭记忆挑。

**时间冲突只提示不拦截**：同一面试官时间重叠时返回警告，仍允许保存，
因为连排或临时加塞是真实存在的需要。

| 操作 | 谁可以 | 行为 |
| --- | --- | --- |
| 安排 | 招聘 HR、HR 负责人、用人经理、超管 | 用人经理只能安排本业务线候选人 |
| 改期／改派 | 同上 | 改派后候选人随之转给新面试官，原面试官不再可见 |
| 取消 | 同上 | 必须填原因；候选人邀请链接立即失效 |
| 查看 | 面试官仅看指派给自己的 | 已取消场次默认隐藏，可按状态筛选 |

**显示名必须可区分**：演示账号的显示名此前被写成角色名，两位面试官都叫「业务面试官」。
已改为人名，老库启动时自动修正（只改仍等于默认角色名的账号，用户改过的不动）。

#### 3.3.5 面试方式与视频面试（R-27）

**平台不自建音视频**，接入公司已有会议工具（腾讯会议、飞书、Zoom 等）。
范围约定不做「AI 面试官与无人化视频面试」，自建音视频还要解决穿透、弱网与录制存储，与本期问题无关。
平台负责的是：把会议入口、时间与身份安全地送到两类人手里，并采集录音同意。

| 方式 | 必填信息 | 面试官入口 | 候选人入口 |
| --- | --- | --- | --- |
| 视频 | 会议链接（仅限 http/https），会议号选填 | 平台账号登录 → 面试日程或准备页点「进入会议」 | 邀请链接 → 「进入视频会议」 |
| 现场 | 面试地点 | 平台内查看地点 | 邀请链接显示地点与到场提示 |
| 电话 | 无 | 按简历联系方式拨打 | 邀请链接提示保持电话畅通 |

**会议链接只接受 http(s)**：它会原样渲染成候选人页面上的按钮，
放行 `javascript:` 等协议就成了面向外部人员的脚本注入入口。

**面试官在准备页就能入会**：准备页顶部显示面试方式、时间、会议号与「进入会议」，
面试官一边开会一边看分层题目与评分锚点，不用再去翻邮件找链接。

#### 3.3.6 P-18 候选人面试邀请页（免登录）

候选人不是平台用户，**不为一场面试注册账号**。安排面试时生成邀请链接，
HR 在面试日程中点「复制候选人链接」，得到一段可直接粘贴到邮件或短信的邀请文本。

| 区块 | 内容 |
| --- | --- |
| 面试信息 | 姓名、岗位、轮次、时间（含星期）、时长、方式、会议号或地点 |
| 入口 | 视频面试的「进入视频会议」按钮，附设备检查提示 |
| 录音同意 | 说明录音用途，**明确写出「不同意不会影响面试结果」**；同意／不同意，面试开始前可修改 |
| 提示 | 链接仅限本人使用，时间不便请联系 HR |

**录音同意三态**：未回复／同意／不同意。「不同意」与「未回复」对面试官意味着不同的动作 ——
前者直接走手动摘要，后者开场要当面再问一次，所以准备页分别给出不同提示。
同意动作写入决策日志，供事后举证。

**邀请链接的安全边界**（这两个接口不要求登录，必须收紧）：

| 约束 | 实现 |
| --- | --- |
| 不可枚举 | 32 字节随机令牌，而非自增 id |
| 不泄露存在性 | 无效、过期、已取消统一返回 404 与同一句提示 |
| 最小返回 | 不含面试官姓名、题目、评分、能力项、简历与联系方式 |
| 可撤销 | 取消或「重新生成链接」后旧链接立即失效 |
| 自动过期 | 面试结束 24 小时后失效 |
| 面试官不可代答 | 面试官端接口不返回邀请令牌，无法替候选人点同意 |

#### 3.3.7 验收标准

| 编号 | 验收点 |
| --- | --- |
| A3-1 | 四层题目各不少于规定题量，每题关联具体能力项 ID 且出题依据可追溯 |
| A3-2 | 敏感话题拦截有效，对抗测试用例零漏出 |
| A3-3 | 时间预算重排功能生效，30 分钟方案总预计时长不超过 32 分钟 |
| A3-4 | 问答对归类到能力项的准确率达标，未覆盖能力项清单完整 |
| A3-5 | **面试官评分区域无任何 AI 预填值** |
| A3-6 | 排除条款最多出 1 道核验题，且不出现「你有没有造假」式提问 |
| A3-7 | **不指定面试官无法安排面试**；同一轮次不能重复安排 |
| A3-8 | 面试官只能看到指派给自己的场次；改派后原面试官立即不可见 |
| A3-9 | 视频面试必须填会议链接，且拒绝非 http(s) 协议 |
| A3-10 | 候选人凭邀请链接免登录查看，返回内容不含面试官、题目、评分与简历 |
| A3-11 | 伪造、过期、已取消的链接统一返回 404；重发后旧链接立即失效 |
| A3-12 | 候选人的录音同意在 HR 与面试官端同步可见，面试开始后不可再改 |

### M4 培训考核（R-11、R-15、R-21 至 R-24）

#### 3.4.1 培训方案配置（R-21）

**交付期新增。** 发布者在生成方案时设定以下参数，**由服务端强制执行**：

| 字段 | 类型 | 必填 | 默认值 | 规则与约束 |
| --- | --- | --- | --- | --- |
| 方案名称 | 文本 | 否 | 自动生成 | 留空则取「岗位名 + 新人培训方案」，60 字以内 |
| 岗位 | 单选 | 是 | 空 | 决定大纲对应哪套能力模型，**选错会生成无关的题** |
| 方案说明 | 文本 | 否 | 空 | 给新人看的背景交代，显示在学习页 |
| 培训开始 | 日期 | 否 | 空 | 留空表示不限制；**新人只能在这个日期之后开考** |
| 培训结束 | 日期 | 否 | 空 | 留空表示不限制；到期后新人无法再开考 |
| 考试限时 | 数值 | 否 | 60 | **10 至 180 分钟**，服务端强制，**考生无法自行加时** |
| 及格分 | 数值 | 否 | 60 | 0 至 100，带教人终评时以此为默认判定线 |
| 公司资料 | 文件 | 否 | 空 | 可直接在弹窗内上传，上传即入库并绑定到本方案 |

**为什么限时与及格分必须由服务端强制**：若由客户端传值，考生只需改一个请求参数就能给自己加时间。
同理，及格线与考试窗口都取自方案记录，不读客户端传值。

**资料未勾选时的行为**：自动引用资料库中未被其它方案占用的文件，并在生成后**明确提示引用了哪几份**，
而不是静默忽略 —— 静默忽略会让发布者以为资料没生效却查不出原因。

#### 3.4.2 培训内容生成（R-22）

输入为岗位能力模型 + 该岗位关联的公司资料与知识库，输出培训大纲与题库。
**生成内容一律标记为草稿，须带教人确认后才可发布给新人。**

| 输出物 | 来源 | 规则 |
| --- | --- | --- |
| 培训大纲 | 能力模型 + 知识库 + 公司资料 | 按能力项组织章节，每章节标注对应能力项与建议学时 |
| 学习材料索引 | 知识库检索 | 指向内部文档原文位置，**不复制正文**，避免版本不一致 |
| 考核题库 | 能力模型 + 知识库 + 公司资料 | 四类题型：单选、多选、情景判断、案例分析 |
| 题目难度 | 模型标注 | 基础／进阶／综合三档，发布时可按比例抽题组卷 |
| 参考答案 | 资料与知识库溯源 | **必须引用文档出处**，无出处的题目标记待人工补充答案 |
| 出题出处 | 引用片段 | 每题标注引自哪份资料的哪一段，供发布者核对 |

**生成质量必须显式告知**：题库生成失败或走了降级路径时，接口返回明确警告，
而不是让发布者自己数题目数量发现问题。

#### 3.4.3 自动判卷规则

| 题型 | 判卷方式 | 规则 |
| --- | --- | --- |
| 单选 | 规则自动判 | 完全匹配即得分 |
| 多选 | 规则自动判 | 全对得满分，漏选得半分，**错选不得分**，规则在卷首说明 |
| 情景判断 | AI 评分加人工确认 | 按预设评分要点给分并列出命中与缺失要点，带教人可调整 |
| 案例分析 | AI 建议加人工终评 | AI 仅给要点覆盖度分析，最终分数由带教人给出 |

**主观题 AI 不给终评分数，只给要点覆盖分析。** 培训考核结果可能影响转正评估，终评权必须在人手里。

判卷结果生成**能力雷达图**（R-15），维度即能力模型的能力项，供带教人定后续培养重点。
考核成绩与试用期表现共同回流至 M5，用于季度复盘能力项权重。

#### 3.4.4 新人学习与考试（R-23）

**交付期新增。** 新人登录后只能看到指派给自己的培训与考核。

| 能力 | 规则 |
| --- | --- |
| 查看培训 | 只返回指派给当前账号的记录，**隔离在查询层实现**，不依赖前端过滤 |
| 学习内容 | 可查看大纲、方案说明、培训窗口与考试规则 |
| 参加考试 | 仅在培训窗口内、且剩余次数大于 0 时可开考 |
| 考试次数 | 由带教人指派时设定，默认 1 次；用完后提示联系带教人 |
| 查看成绩 | 可看自己的判卷结果与雷达图，**看不到自己的风险信号明细** |
| 查看他人 | 严格禁止，越权访问返回 403 |

**考试规则对新人透明**：界面上直接显示限时多久、多少分算过、什么时候截止，
而不是开始考试后才发现 —— 避免因规则不透明导致的争议。

#### 3.4.5 考核反作弊（R-24）

**交付期新增。** 采用三层设计，并明确规定**只有第一层是真实防线**。

| 层级 | 机制 | 定位 | 具体措施 |
| --- | --- | --- | --- |
| **第一层：服务端强制** | 不可绕过 | **真实防线** | 答案不下发（判卷全在服务端）；开考即冻结试卷；服务端计时；每人随机组卷与选项乱序；限次与幂等交卷；超时不可提交 |
| **第二层：客户端信号** | 可绕过 | **仅作线索** | 切屏、粘贴、复制、右键、开发者工具、多标签页、打印等浏览器事件上报 |
| **第三层：人工复核** | 最终判断 | **由人定夺** | 高风险作答进入带教人复核队列并附信号明细，由人决定是否作废 |

**第二层的信号权重与阈值**（后台可查，权重固定）：

| 信号 | 权重 | 信号 | 权重 |
| --- | --- | --- | --- |
| 开发者工具 | 6.0 | 多标签页 | 5.0 |
| 粘贴 | 4.0 | 打印 | 4.0 |
| 失焦长时间 | 3.0 | 快速交卷 | 3.0 |
| 复制 | 2.0 | 右键菜单 | 2.0 |
| 全程未聚焦 | 2.0 | 切屏 | 1.0 |
| 页面隐藏 | 1.0 | 异常缩放 | 1.0 |

- 同类信号**封顶计数**（防止单类信号刷分），再叠加答题速度启发式。
- 风险等级：`≥ 15` 可疑 / `≥ 5` 关注 / 其余正常。
- **风险等级只决定是否进入复核队列，绝不影响分数。**

##### 为什么客户端信号不能自动判失败

浏览器事件**技术上不可能防住有心作弊的人**，而且会大量误伤无辜场景：
接电话时切屏、输入法弹窗导致失焦、笔记本合盖导致页面隐藏。
若据此自动判失败，会直接违背需求分析中的洞察二 ——
**误杀的代价远高于漏放**，在考核场景同理。

因此这三层的关系是：服务端让「作弊拿不到答案」，客户端信号「把可疑的挑出来给人看」，
最终由带教人看证据决定。

#### 3.4.6 考核复核台（P-15）

| 功能 | 规则 |
| --- | --- |
| 复核队列 | 按风险分降序排列，附信号明细（时间、类型、次数） |
| 作废 | 带教人可作废某次作答，须填复核备注；**作废后返还考试机会** |
| 终评 | 带教人给出最终分数，及格线取方案的及格分 |
| 试用期回写 | 可回写试用期表现，进入回流样本池 |

## 4 AI 能力规格

本章是 AI 产品 PRD 与常规功能 PRD 的**主要差异所在**。常规接口只需定义入参出参，
而模型输出存在不确定性，因此必须额外约定输出结构、置信度口径、降级策略与失败边界，
否则研发无法判断什么算正常、什么该兜底。

### 4.1 能力清单

| 能力 | 输入 | 输出 | 调用方式 | 失败处理 |
| --- | --- | --- | --- | --- |
| 简历解析 | 文件字节流 | 结构化字段 JSON | 异步 | 转解析异常，进人工补录队列 |
| 能力项抽取 | 结构化简历 | 能力项候选与证据 | 同步 | 重试后转人工，**不给默认值** |
| 匹配打分 | 简历 + 能力模型 | 总分与逐项结果 | 同步 | **失败不落分**，状态留在待打分并告警 |
| 面试题生成 | 简历 + 能力模型差集 | 题目数组 | 同步 | 降级为按能力项的通用题模板 |
| 问答归类 | 逐字稿 + 能力模型 | 能力项问答映射 | 异步 | 降级为仅提供原始逐字稿 |
| 题库生成 | 能力模型 + 知识库 | 题目与参考答案 | 异步 | 保留已生成部分，提示继续生成 |
| 主观题判卷 | 答案 + 评分要点 | 要点覆盖分析 | 同步 | 降级为仅人工判卷 |
| 培训大纲生成 | 能力模型 + 知识库 | 章节大纲 | 异步 | 保留已生成部分 |
| JD 分析 | 岗位描述 | 能力项候选池 | 同步 | 转人工 |

### 4.2 输出结构约定

所有能力统一返回**三段结构**：结果体、证据体、元信息。

| 段 | 必含字段 | 校验规则 |
| --- | --- | --- |
| 结果体 | 业务字段 | 按各能力的 schema 强校验，枚举值不在约定集合内即判为失败 |
| 证据体 | 原文片段、起止位置 | **打分类能力必须非空**；证据位置越界或无法匹配原文即判为失败 |
| 元信息 | 模型版本、提示词版本、置信度、耗时 | 版本号必须可追溯到提示词库的具体版本，供回归对比 |

**硬性校验（实现层）**：

1. 结果体 schema 校验失败 → 整个调用判为失败，走降级，**不把不完整结果渲染给用户**；
2. 打分类能力证据体为空 → 判为失败（对应「无证据不给分」）；
3. 模型自己返回的元信息被丢弃，**版本号以代码侧配置为准** ——
   否则模型可能编造一个版本号，让归因失效。

#### 为什么把版本号写进输出

线上出现效果波动时，第一件要确认的是**当时跑的是哪个版本**。没有版本号就只能靠时间猜，归因成本极高。
把模型版本与提示词版本作为输出必含字段并写入决策日志，效果看板才能把指标波动和变更点对齐，
这也是离线回归能生效的前提。

### 4.3 置信度与降级

置信度口径统一由算法侧定义并文档化。产品侧只消费**分档结果**，不在界面展示原始数值，
避免用户对数字产生错误解读。

| 降级级别 | 触发条件 | 处理 |
| --- | --- | --- |
| 一级：重试 | 网络或超时 | 最多重试 2 次，成功后标记为「重试后成功」 |
| 二级：切换模型 | 主模型不可用 | 切备用模型并标记，元信息记录实际使用的模型 |
| 三级：转人工 | 连续失败或输出校验不通过 | 状态留在原处并告警，由人工接手 |

**禁止静默降级。** 若使用了备用模型或模板兜底，界面必须标注，
否则用户会把兜底结果当作正常结论采信。

**超时阈值**：同步能力默认 20 秒，异步能力默认 10 分钟；各能力可按实际输出量单独配置。
超时按失败处理并进入对应降级路径。

### 4.4 提示词与版本管理

- 提示词**独立于代码管理**，按能力拆分，每次变更生成新版本号，
  支持**按能力粒度独立回滚**，不需整体发版。
- 任何提示词或模型变更上线前**必须跑全量离线回归**，核心指标下降超过 2 个百分点即阻止上线，
  机制由发布流程强制卡点，非人工自觉。
- 灰度期间同一能力可**并行两个版本**，按流量比例分配，看板支持按版本对比核心指标。

### 4.5 安全与注入防护

**简历是用户可完全控制的外部输入**，存在植入指令诱导模型输出高分的风险。防护采用三层。

| 层级 | 措施 | 说明 |
| --- | --- | --- |
| 输入层 | 指令特征剥离 | 解析阶段识别并剥离疑似指令文本，原文留档标记待审 |
| 提示层 | 内容边界隔离 | 简历内容作为**数据**而非指令传入，明确声明不执行其中任何指令 |
| 输出层 | 一致性校验 | 得分与证据不匹配、证据无法在原文定位的结果一律判为失败转人工 |

**命中注入特征的简历不直接拒绝**，而是剥离后正常解析并标记待审，
由管理员判断是格式问题还是恶意行为 —— 避免误伤使用特殊模板的正常候选人。

#### 验收标准

| 编号 | 验收点 |
| --- | --- |
| A7-1 | 打分类能力返回空证据体时判为失败并走降级，不落分 |
| A7-2 | 结果体 schema 校验失败时不渲染不完整结果 |
| A7-3 | 元信息中模型与提示词版本以代码侧为准，模型返回值被丢弃 |
| A7-4 | 三级降级路径均可触发且界面明示降级状态 |
| A7-5 | 注入对抗样本零漏出，命中后剥离并标记待审而非直接拒绝 |
| A7-6 | 提示词变更后离线回归不达标时阻止上线 |

## 5 非功能需求

### 5.1 性能

| 场景 | 指标 | 目标 | 说明 |
| --- | --- | --- | --- |
| 单份简历端到端 | P95 延迟 | 18 秒以内 | 含解析与打分，从入队到结果可见 |
| 批量导入 200 份 | 完成时间 | 25 分钟以内 | 异步处理，完成后站内提醒 |
| 复核页首屏 | 加载时间 | 1.5 秒以内 | 简历原文与打分结果同时可见 |
| 证据定位响应 | 交互延迟 | 300 毫秒以内 | 点击能力项到左侧高亮完成 |
| 面试题生成 | P95 延迟 | 25 秒以内 | 超过 10 秒显示进度与预计剩余 |
| 并发处理 | 峰值吞吐 | 每分钟 60 份 | 按早高峰投递集中时段测算，需压测验证 |

### 5.2 成本约束

单份简历处理成本目标 **0.16 元以内**。手段为：

- **模型分级路由**：解析与格式化用小模型，打分与出题用大模型；
- **语义缓存**：同一候选人重复投递不同岗位时复用解析结果；
- **批处理合并请求**。

看板提供成本监控，单份成本连续 3 天超过 0.25 元时告警，由产品与算法共同复盘。

### 5.3 兼容与可用性

- 浏览器支持 Chrome、Edge 最近两个大版本，不支持 IE。
- 移动端本期仅支持面试准备页与评估报告的**查看**，不支持复核操作。
- 核心链路可用性目标 99.5%。**模型服务不可用时，平台降级为纯人工模式**，
  简历仍可正常查看与流转，不因 AI 故障阻断招聘业务。
- 无障碍：关键操作支持键盘完成，表单错误提示与输入控件关联。

### 5.4 数据权限与隔离

- 按业务线做数据隔离，跨业务线不可见候选人信息。
- 面试官仅可见被指派候选人。
- **知识库检索结果受同一套权限约束**，不得通过检索绕过隔离。
- 系统管理员可配置参数但不可查看简历正文与联系方式。
- 法务审计角色全量只读且**不含联系方式**。
- 简历留存期对齐公司数据留存政策，到期自动清理；候选人提出删除申请后按公司政策时限完成，
  删除范围含衍生的结构化数据与索引。

### 5.5 日志与审计

| 日志类型 | 记录内容 |
| --- | --- |
| AI 决策日志 | 输入摘要、模型与提示词版本、输出结论、置信度、耗时、是否降级 |
| 人工操作日志 | 操作人、动作、时间、否决原因、变更前后状态 |
| 配置变更日志 | 阈值与参数的变更前后值、操作人、生效时间 |
| 权限与访问日志 | 谁在何时查看了哪位候选人的简历，支持异常访问排查 |
| 注入拦截日志 | 命中特征、处理方式、原文留档位置 |

日志保留期不短于 3 年，满足劳动争议举证需要；**日志本身不可编辑，仅可追加**。

## 6 埋点方案

埋点服务于两个目的：**验证效果指标、定位使用障碍**。只埋能驱动决策的事件，不做全量无差别采集。

| 事件 | 触发时机 | 关键属性 | 用途 |
| --- | --- | --- | --- |
| `resume_scored` | 打分完成 | 岗位、分档、总分、耗时、模型版本 | 分层占比与延迟监控 |
| `review_action` | 采纳或否决 | 动作、否决原因、停留时长 | 一致率与复核效率 |
| `evidence_click` | 点击查看依据 | 能力项、是否展开抽屉 | 验证证据溯源是否真被使用 |
| `pool_rescue` | 待定池捞回 | 捞回原因、原分档 | 误杀线索追踪 |
| `question_action` | 题目采纳删改 | 动作、层级、能力项 | 采纳率与出题质量分析 |
| `report_confirm` | 评估报告确认 | 修改比例、耗时 | 归类质量 |
| `exam_submit` | 考核提交 | 题型、得分、能力项、信号数 | 考核有效性验证 |
| `exam_start` | 开始考试 | 方案、剩余次数 | 考试链路漏斗 |
| `ai_degrade` | 发生降级 | 降级级别、原因、能力名 | 稳定性监控 |
| `interview_consent` | 候选人表态录音意愿 | 场次、是否同意 | 录音同意率，判断录音路径是否可行 |

#### `evidence_click` 为什么值得单独埋

证据溯源是本产品**最重要的设计决策**，但它是否真的被使用无法靠主观判断。
如果上线后点击率极低而采纳率很高，说明用户在**盲目采纳**而非验证 ——
这反而是危险信号，需要调整交互而不是庆祝采纳率。

这个埋点的作用是**验证设计假设本身是否成立**。

## 7 验收与上线

### 7.1 双线验收

功能验收与效果验收并行，两线均通过才允许灰度，灰度稳定才允许全量。

| 验收项 | 门槛 | 不达标处理 | 执行方式 |
| --- | --- | --- | --- |
| 功能用例通过率 | 100% | 阻止上线 | P1 与 P2 缺陷全部关闭，P3 可带单上线 |
| 字段抽取准确率 | 不低于 95% | 阻止上线 | 测试集含扫描件，逐字段比对 |
| 结论一致率 | 不低于 85% | 延期放量 | 精标集，对比 AI 分档与面试官实际结论 |
| 误杀率 | 不高于 2% | **一票否决** | 自动分流样本盲标复核 |
| 引用准确率 | 不低于 92% | 延期放量 | 抽检证据，定位错误即计不准确 |
| 敏感特征零泄漏 | 强制 | **一票否决** | 代码级校验加输出抽检双重确认 |
| 去偏验证 | AIR 高于 0.9 | **一票否决** | 分组通过率比值检验 |
| 注入对抗测试 | 零漏出 | 阻止上线 | 构造样本，含隐藏文字与白字注入 |
| P95 延迟 | 18 秒以内 | 性能优化后重测 | 压测环境按峰值吞吐验证 |
| 面试题采纳率 | 不低于 70% | 可灰度观察 | 灰度期真实使用数据统计 |

> **本仓库可执行的验证范围**：功能验收与**结构性**效果验证可直接运行 ——
> 「无证据不给分」「选项乱序后答案重映射」「限次与超时不可绕过」「越权访问被拒」
> 等约束由自动化测试覆盖。依赖真实数据的效果指标（一致率、误杀率、AIR）
> 需接入真实 ATS 后测量，本仓库不提供也无法伪造。

### 7.2 灰度与放量

| 阶段 | 范围 | 观察周期 | 放量条件 |
| --- | --- | --- | --- |
| 内测 | HR 团队 | 1 周 | 功能验收通过，无阻断性问题 |
| 灰度一 | 数个部门约 18% 流量 | 1 周 | 核心指标达标，无 P1 缺陷，误杀率复核通过 |
| 灰度二 | 扩至约 50% | 2 周 | 指标稳定，采纳率达标 |
| 全量 | 各业务线 | 持续 | 灰度二各项达标，SOP 与培训材料就绪 |

- 灰度期间**保留一键回滚开关**，可按业务线维度关闭 AI 能力回退为纯人工，回滚不影响已流转的候选人状态。
- 每阶段结束出具放量评审结论，含指标现状、发现的问题、是否放量的建议。

### 7.3 上线配套

- **SOP 文档**：HR 复核操作规范、面试官使用指引、带教人考核发布流程各 1 份。
- **培训宣讲**：按业务线各 1 场，重点说明 AI 只做辅助、否决权在人、如何使用证据验证结论。
- **反馈通道**：产品群 + 需求收集表单，双周汇总排期，反馈处理结果回复提出人。
